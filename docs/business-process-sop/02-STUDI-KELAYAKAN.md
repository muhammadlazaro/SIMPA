# Tahap 2 - Studi Kelayakan

## Tujuan
Menilai kelayakan bisnis, teknis, biaya, risiko, dan prioritas portofolio.

## Trigger Masuk
Pengajuan lolos validasi administrasi.

## Input Wajib
- Dokumen pengajuan tervalidasi
- Data volume pengguna/transaksi (estimasi)
- Constraint regulasi/keamanan

## Aktivitas Inti
1. Analisis manfaat vs biaya (high-level).
2. Analisis risiko (operasional, keamanan, ketergantungan).
3. Penentuan prioritas terhadap pengajuan lain (portfolio triage).

## Output Wajib
- Dokumen studi kelayakan
- Rekomendasi: lanjut/tunda/tolak
- Estimasi effort level (S/M/L)

## Gate ke Tahap Berikut
- Rekomendasi disetujui Pengelola Aplikasi
- Prioritas resmi ditetapkan
- Risiko utama punya rencana mitigasi awal

## SLA
- Penyelesaian studi: maksimal 5 hari kerja.

## RACI Ringkas
- R: Pengelola Aplikasi, Analis Desain
- A: Pengelola Aplikasi
- C: Unit Kerja, Tim Implementasi, Tim Uji Keamanan
- I: Operasional/Support

## Risiko dan Mitigasi
- Risiko: Semua pengajuan dianggap prioritas tinggi.
- Mitigasi: Terapkan skor prioritas berbasis dampak, urgensi, risiko.

## Bukti Audit
- Dokumen studi kelayakan final
- Notulensi keputusan triage
- Status gate Studi Kelayakan -> Analisa dan Desain
